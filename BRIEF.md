# Бриф: сайт студии addictcode «Автоматизируем»

> Концепт пересмотрен владельцем много раз: «Конвейер», «Кубики», «Лента», «Живая система», карта-схема, «Сборка». Затем владелец попросил убрать карту и всю старую идею целиком: нужен вау-эффект на первом экране, сильный моушен по скроллу, красиво, но не кричаще, фокус на одном понятном предложении вместо длинного списка услуг, работы коротко и ясно. Сделан концепт «Одна заявка». Разделы «Предложение», «Концепт», «Страница», «Дизайн» и «Техника» описывают актуальную версию, факты о кейсах не менялись.

Сайт-портфолио мини-студии разработки addictcode (владелец и двое разработчиков, которые ему помогают). Цель: показывать фриланс-заказчикам (сайты, Telegram-боты, автоматизация, CRM) и рекрутерам. Сайт должен запоминаться за счёт 3D и моушена, но быстро грузиться на телефоне и не выглядеть шаблонно.

## О студии (что можно писать)

- Сайт оформлен от лица студии: название `addictcode`, подпись «студия разработки», тексты от первого лица во множественном числе («собираем», «ответим»). Имён и фамилий участников на сайте нет, город и учёба не указываются. Число участников и их роли на сайте не называются.
- Делает: сайты с админкой и заявками, Telegram-ботов, парсеры и мониторинг, CRM и внутренние системы, интеграции с LLM.
- Стек: Java 17–25, Spring Boot 3–4, PostgreSQL, Redis, Docker, GitHub Actions; TypeScript, React, Next.js, Vite; Python (FastAPI, aiogram); three.js.
- GitHub: https://github.com/addictcode
- Telegram: @heaphog. Ник лежит в `src/content/profile.ts`, ссылка `https://t.me/<ник>` собирается из этого поля.

Нельзя упоминать: имена и фамилии участников, место работы, рабочую почту, любой email, названия клиентов (см. «Кейсы»).

## Предложение

Студия делает разное, поэтому крючок общий: **«Автоматизируем [заявки]. Рутину делает код, а не люди.»** Слово в плашке само меняется: заявки → ответы клиентам → запись → сбор цен → отчёты. Под ним — меню из шести готовых решений на выбор, у каждого цена «от», срок и проект, где это уже работает:

| Решение | Цена от | Срок от | Подтверждение |
|---|---|---|---|
| Telegram-бот для заявок и записи | 6 000 ₽ | 3 дня | заявки в Telegram у дилера |
| AI-ассистент по документам клиента | 15 000 ₽ | 5 дней | LLM в TenderRadar |
| Заявки в CRM или таблицу | 5 000 ₽ | 2 дня | заявки у дилера, CRM/ERP |
| Сайт или лендинг с заявками | 25 000 ₽ | 7 дней | сайт дилера |
| Парсинг и мониторинг | 5 000 ₽ | 2 дня | TenderRadar, парсер каталога дилера |
| Система под ключ | 150 000 ₽ | 6 недель | CRM/ERP |

Цены подобраны по просьбе владельца как стартовые, для первых отзывов. В английской версии — в долларах. Условия работы: предоплата 50%, два круга правок, 14 дней бесплатного исправления ошибок, код и доступы у клиента, поддержка от 3 000 ₽ в месяц. Цены и условия меняются только в `src/content/ru.ts` и `en.ts`.

Демо-прототипы из прежних версий не возвращать без запроса владельца.

**На сайте показываем только серьёзные проекты:** сайт дилера, CRM/ERP и TenderRadar. Vinted-бот, Pulse и distributed-task-engine по решению владельца на сайте не упоминаются и как подтверждение услуг не используются, хотя факты о них ниже остаются.

## Концепт

Первый экран: «Автоматизируем [плашка]» — светлая плашка со сменяющимся словом, ниже «Рутину делает код, а не люди». При скролле плашка вылетает из фразы, превращается в карточку и на примере одного клиента показывает три продукта студии:

- **Сайт ловит.** Карточка встаёт формой в окно сайта, задача печатается по мере скролла, кнопка нажимается.
- **Бот отвечает.** Снизу поднимается телефон: заявка приходит менеджеру с галочками ✓✓, клиенту уже ответил AI-ассистент.
- **CRM доводит до оплаты.** Карточка прыгает по колонкам доски CRM (заявка, КП, договор, работа, оплата) до «Оплачено».

Слева сменяются три шага с фактами из кейсов, в конце — «Всё это — одна команда: можно по отдельности или вместе». В последнем разделе та же плашка — «Ваша [заявка] — следующая», настоящая заявка в Telegram.

Знак студии — две галочки ✓✓.

## Страница

Одна страница, сверху вниз:

| Раздел | Содержимое |

| Полоса стека | Технологии бегущей строкой |
| Работы (`#works`) | Три проекта строками: сайт дилера, CRM/ERP, TenderRadar; нажатие раскрывает факты, стек и схему проекта. На широком экране схема плывёт за курсором. У сайта дилера — живой поиск по раскладке |
| Условия (`#terms`) | Пять шагов работы и четыре условия |
| Вопросы | Шесть частых вопросов, раскрываются по нажатию |
| Связаться (`#contact`) | «Ваша [заявка] — следующая.» и карточка заявки в Telegram |
| Подвал | Название, одна фраза, Telegram, GitHub |

Схемы проектов в «Работах» нарисованы кодом: без скриншотов, названий и данных.

## Кейсы (факты; не выдумывать сверх этого)

### 1. Сайт для дилера ворот и автоматики, Минск — АНОНИМНО
Коммерческий заказ, сайт в продакшене. Название компании, домен, логотип, фото товаров и скриншоты НЕ показывать. Иллюстрация: схематичный макет интерфейса, нарисованный кодом.
- Перенос со старого WordPress: каталог 421 позиция, собран парсером на Python.
- Next.js 16, React 19, TypeScript, Tailwind 4.
- Каталог с фильтрами и поиском, который понимает неверную раскладку («ghbdjl» → «привод»).
- Заявки уходят в Telegram и на почту, с резервным журналом в админке.
- Админка: откат на 40 версий назад, защита от одновременного редактирования двумя людьми.
- Кабинет дилера с персональными ценами и выгрузкой в Excel.
- 301-редиректы со старых адресов, разметка schema.org, SSL Labs A+.
- Ежедневная сверка цен с поставщиком и уведомления в Telegram.

### 2. Vinted Telegram Bot — публично
https://github.com/addictcode/vinted-telegram-bot
- Следит за сохранёнными поисками на Vinted и присылает новые объявления за секунды. Сделан для собственного ресейла.
- Java 17, Spring Boot 3.2, PostgreSQL + Flyway, Jsoup, Docker.
- Карточка товара по ссылке, список отслеживания, отдельная тема форума под каждый поиск.
- Обход ограничений: backoff, бюджет запросов на прокси. Пережил отключение JSON API площадки (переведён на чтение страницы каталога).
- Скриншотов нет: на сайте вместо них схема, нарисованная кодом.

### 3. CRM/ERP для сервисной компании — ОБЕЗЛИЧЕННО
Коммерческий заказ. Не называть отрасль точнее, чем «выездной сервис с бригадами и техникой», не давать ссылок на демо, не показывать скриншоты. Иллюстрация: схематичный макет кодом.
- Полный цикл: заявка → коммерческое предложение → договор → планирование бригад → выполнение → акт → счёт → оплата → аналитика.
- Java 25, Spring Boot 4.1, Spring Modulith: 15 модулей, у каждого своя схема PostgreSQL. PostGIS, Flyway, JWT.
- React 19, TypeScript, TanStack Router/Query, карты MapLibre, графики ECharts, клиент API сгенерирован из OpenAPI.
- Ролевой интерфейс (директор, менеджер, диспетчер, исполнитель) и мобильный кабинет исполнителя.
- Защита от двойного бронирования на уровне базы, ключи идемпотентности, outbox.
- Тесты: Testcontainers, ArchUnit, Playwright, нагрузочный k6. CI на GitHub Actions.

### 4. Pulse — публично
Репозиторий: https://github.com/addictcode/pulse-crypto-screener · Демо: https://addictcode.github.io/pulse-crypto-screener/
Подавать как «дашборд реального времени с Telegram-алертами», а не как крипто-продукт.
- Около 530 инструментов в реальном времени по WebSocket.
- Java 25, Spring Boot 4.1, PostgreSQL + Liquibase; фронт на TypeScript + Vite, Lightweight Charts, three.js.
- Детекция сигналов на сервере с отслеживанием исхода; честный отчёт о том, что сигналы направление не предсказывают.
- Нагрузочные тесты k6, бюджеты на размер и CLS в Playwright, 5 workflow в CI.
- Картинка: `assets-src/pulse/og.png`.

### 4б. distributed-task-engine — публично
Репозиторий: https://github.com/addictcode/distributed-task-engine · Демо: https://addictcode.github.io/distributed-task-engine/
- Очередь задач: приоритеты на Redis sorted set, захват через `FOR UPDATE SKIP LOCKED`, повторы с backoff, dead-letter, heartbeat воркеров, дашборд по STOMP.
- Java 21, Spring Boot 3.5, PostgreSQL, Redis.

### 5. TenderRadar — без ссылки (репозиторий приватный)
Обязательная пометка: «работает на демо-данных».
- Агрегатор тендеров из нескольких площадок в одну базу без дублей.
- Морфологический поиск, лента в стиле inbox, уведомления в Telegram и на почту, оценка релевантности через LLM.
- Python 3.12, FastAPI, SQLAlchemy 2 async, Redis-очередь, aiogram 3; React 18, TanStack Query/Virtual.
- Картинки: `assets-src/tenderradar/*.png` (данные в них синтетические).

## Дизайн

- Образ: тёмная студийная вёрстка. Почти чёрный фон с лёгким зерном, светлый текст, один акцент — лайм `#c8f04a`. Главный объект — светлая карточка заявки.
- Крупный гротеск (Geologica) с плотной разрядкой, моноширинный (Martian Mono) для меток.
- Вау-эффект: на первом экране строки заголовка поднимаются по очереди, плашка «заявка» выпрыгивает и пульсирует кольцами, на фоне всплывают и тают пустые карточки заявок. При скролле — полёт карточки через три сцены. Курсор слегка наклоняет летящую карточку.
- Не кричать: акцент только на кнопках, галочках и статусах.
- Запрещено: фиолетовые градиенты, glassmorphism, свечение, эмодзи вместо иконок, карточки-близнецы в три колонки, «звёздное небо» из частиц.
- Шрифты обязаны поддерживать кириллицу.

## Техника

- Vite + React + TypeScript, статическая сборка. Без three.js и библиотек анимации.
- Путь заявки: секция высотой 600svh, внутри закреплённая сцена. Свой обработчик скролла сглаживает прогресс и двигает элементы через `transform`; React меняет только дискретное состояние карточки (напечатанные буквы, галочки, колонка). Код — `src/components/Journey.tsx`, декорации — `src/components/scenes.tsx`.
- Контент в `src/content/*.ts` (RU и EN), название студии и ссылки — `src/content/profile.ts`.
- RU по умолчанию, переключатель RU/EN, выбор запоминается.
- При `prefers-reduced-motion` и с параметром `?static` — статичная версия: первый экран и три шага друг под другом, в каждой декорации стоит карточка, тот же текст.
- Весь содержательный текст в обычном HTML, декорации скрыты от скринридеров.
- Мета-теги, OG-картинка (первый экран), favicon со знаком ✓✓.
- `assets-src/` — исходники картинок проектов; сейчас в сборку не попадают, схемы рисуются кодом.
